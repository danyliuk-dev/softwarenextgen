<section id="first-report"><h2>3. Build your first report</h2>
<p>This exercise creates a one-page equipment list without code.</p>
<p><a id="download-equipment" href="http://127.0.0.1:5274/api/examples/equipment" download="equipment.nrproject.json">Download Equipment project</a> to inspect the finished example. Downloading does not change your report. Save your current work, then return to Studio and use <strong>Open project</strong> to open the downloaded file. It includes fictional data and uses no scripts. To learn by building it yourself, follow the steps below.</p>
<ol><li>Choose <strong>New report</strong>, name <code>Equipment</code>, A4, Portrait, then <strong>Create report</strong>.</li>
<li>Open <strong>Data → JSON</strong> and enter:</li></ol>
<pre>{
  "items": [
    {"name": "Monitor", "quantity": 8},
    {"name": "Desk", "quantity": 2},
    {"name": "Chair", "quantity": 12}
  ]
}</pre>
<ol start="3"><li>In <strong>Data → Table</strong>, choose <code>items</code> and confirm three rows.</li>
<li>In <strong>Design → Insert → Text</strong>, enter <code>Equipment list</code>. Select it, set Home → Size to 20 and enable Bold.</li>
<li>Open <strong>Page → Parameters → Add parameter</strong>. Set Name <code>company</code>, Type <code>string</code>, Required, Use default and Default value <code>Example Company</code>. Apply parameters.</li>
<li>Add another Text: <code>Company: {{parameters.company}}</code>.</li>
<li>Insert a Table. Set Data source to <code>items</code>. Keep two columns: Item / field <code>name</code> / weight 2; Quantity / field <code>quantity</code> / weight 1 / format <code>N0</code>. Use Add source fields if needed. Leave Positioning as flow.</li>
<li>Open <strong>Page → Properties</strong>. Set Footer to <code>Page {page} / {pages}</code>.</li>
<li>Choose <strong>Generate preview</strong>. Expect Example Company and Monitor 8, Desk 2, Chair 12, with Page 1 / 1.</li>
<li>Open Run with parameters, edit company and Cancel: the original value remains. Repeat with Generate preview: the new company is accepted.</li>
<li>Save project, export PDF, then reopen the saved project and compare the result.</li></ol>
<p>For practice, add a Page break followed by Text <code>Notes</code>. Preview should show a second page. Undo removes the last template edit. Long flow tables paginate automatically; do not insert breaks between their rows.</p></section>

<section id="data"><h2>4. Data and bindings</h2>
<p>The input is a JSON object, not a spreadsheet. Upload JSON or edit it directly. Arrays supply table rows. Nested objects are addressed using dot-separated paths.</p>
<table><thead><tr><th>Location</th><th>Example</th><th>Meaning</th></tr></thead><tbody>
<tr><td>Text / header / footer</td><td><code>{{data.customer.name}}</code></td><td>Read a scalar from input data.</td></tr>
<tr><td>Text / header / footer</td><td><code>{{parameters.company}}</code></td><td>Read a report parameter.</td></tr>
<tr><td>Table Data source</td><td><code>items</code></td><td>Array path from the data object.</td></tr>
<tr><td>Column Field</td><td><code>quantity</code></td><td>Path relative to each row, not <code>items.quantity</code>.</td></tr>
<tr><td>Header / footer only</td><td><code>{page} / {pages}</code></td><td>Current and total printed pages.</td></tr>
</tbody></table>
<p>Bindings are paths, not arbitrary expressions. Use column Expression for numeric table calculations; use beforeRender for other computations and bind its result. Missing paths and invalid types produce errors. Dictionary can create a new text block or insert a binding at the selection/caret in selected text.</p>
<p>Data → Table displays 100 rows per page, up to 50 columns. Find rows searches the chosen array; column headers cycle ascending, descending and original order. Reset sort restores source order. These operations affect inspection only, not JSON or report output. Use Design → Table → Sort by to sort report output, or beforeRender for advanced ordering/filtering. Dates are supplied as strings. XLSX import and explicit HTTP/SQL/JSON/object refresh are described below.</p></section>

<section id="design"><h2>5. Design, pages and formatting</h2>
<p>Select a block in Report tree or on the sheet, then edit its properties. Insert offers Text, Table, Image and Page break. Home controls text style, duplicate/delete and Copy style / Apply style. Layout changes order and aligns fixed frames. Edit JSON exposes the template; Open block designer returns to visual editing.</p>
<h3>Pages and text</h3><p>Page → Properties edits Width, Height, Margin, Header and Footer. Report dimensions use points: 72 pt = 1 inch. Dialog geometry uses CSS pixels instead. Header/footer must fit on one line. Text wraps and preserves explicit line breaks; use Space after for separation. Copy style transfers size, bold, color and alignment, not content or geometry.</p>
<h3>Tables</h3><p>Set the array source and columns. Width weight is relative, not an absolute width. Add source fields suggests scalar fields from data; manually enter paths for empty arrays. Move left/right and Duplicate column retain column settings. Use N0–N6 or F0–F6 for numbers, column alignment, cell padding, header color and alternating stripe color. Numeric formatting is invariant, not browser-locale dependent. Headers repeat across pages; very tall rows may continue on the next page. Nested grouping and master-detail are available; merged cells are not supported.</p>
<h3>Filtering report rows</h3>
<ol><li>Select a Table. Enter a row field (such as <code>amount</code>) in <strong>Filter field</strong>. Nested paths and undisplayed fields are allowed.</li><li>Choose <strong>Filter condition</strong>: Equals, Does not equal, Greater than, At least, Less than, At most, Contains, Is null or Is not null.</li><li>For conditions other than Is null / Is not null, choose <strong>Filter value source → Constant</strong>, then set <strong>Filter value type</strong> (string/number/boolean) and <strong>Filter value</strong>. Enter plain text without JSON quotes. Changing type resets the value to empty text, 0 or false.</li><li>Generate preview. Clear Filter field to disable; Undo/Redo and Save project retain the settings.</li></ol>
<p>Processing order is filter → sort → group → aggregate. Only surviving rows contribute to totals and groups; source JSON stays unchanged. No matches produce an empty table with zero Sum/Count and blank Average/Min/Max. Data → Table search still affects inspection only. Up to 20 conditions can use All/Any; use grouped filters for nested conditions and beforeRender for advanced transformations.</p>
<p>Try grouped-orders: amount / At least / number / 80 keeps Monitor and Desk, amount total 205.50 and quantity 3. Value 1000 leaves no rows. customer / Contains / string / North keeps Monitor and Chair, total 200.00. Is null on customer keeps none; Is not null keeps all six. Export PDF and reopen the project to verify.</p>
<p>Non-null field and value types must match; numeric strings are not converted. Numbers compare as decimal; text/Contains are ordinal and case-sensitive. Contains requires text; empty text matches every non-null string. Boolean supports Equals/Does not equal. Null matches Is null and Does not equal a supplied value, but no other ordinary comparison. Is not null accepts any non-null value. Missing fields are errors even for Is null. Invalid definitions fail even on empty sources.</p>
<h3>Combining conditions with All / Any</h3>
<p><strong>Add filter</strong> adds an Additional filter block. It copies the primary condition when present, otherwise the last additional condition; with none, it starts with Is not null on the first detected field. Edit field/condition/value source in that block. Each condition can use its own constant or report parameter.</p>
<p><strong>Match conditions → All (AND)</strong> requires every condition; <strong>Any (OR)</strong> requires at least one. A row matching several OR conditions is counted once. All is the default. There are at most 20 conditions including the primary one; Use grouped filters converts these conditions to a nested AND/OR tree.</p>
<p>Try samples/combined-filters.nrtemplate with grouped-orders.data.json: amount ≥ minAmount (default 80) plus customer Equals North. All gives Monitor and 125.50; Any gives Monitor, Chair and Desk, total 280.00. Test Undo/Redo, PDF and save/reopen.</p>
<p><strong>Remove filter</strong> removes that additional condition; clearing a Filter field removes only that condition. <strong>Clear filters</strong> removes all conditions in one Undo step. No conditions include every row in either mode. Removing the extra condition in the sample gives 205.50; clearing all gives 310.30.</p>
<p>Every condition is checked for every source row without short-circuiting, so OR cannot hide a missing-field or type error in another condition. Definitions and parameters are checked even with no source rows. Filtering still precedes sorting, grouping and totals without changing source JSON.</p>
<h3>Filter from a report parameter</h3>
<ol><li>In Page → Parameters, add <code>minAmount</code>, Type number, Required, Default 80; Apply parameters.</li><li>Select the Table: Filter field <code>amount</code>, condition At least. Choose <strong>Filter value source → Report parameter</strong> and <strong>Filter parameter → minAmount</strong>.</li><li>Generate preview uses the current/default value. Open Run with parameters and change the minimum: Generate applies it, Cancel preserves the prior values and report.</li></ol>
<p>Try samples/parameter-filter.nrtemplate with samples/grouped-orders.data.json: default 80 gives Monitor + Desk and total 205.50; 100 gives Monitor and 125.50; 0 gives all rows and 310.30. Save/reopen the project to preserve the binding and run values. PDF matches the last generated snapshot, so generate again after changing parameters. Undo/Redo supports binding edits.</p>
<p>The selector lists scalar string/number/boolean parameters. Contains requires string; ordered comparisons require string/number; equality also supports boolean. The value must match the data field type. Unknown/deleted parameters and string[] are rejected. Supply defaults or run values for number/boolean: an omitted optional value does not disable the filter. Empty string remains valid; empty Contains matches all non-null text. Decimal range rules still apply.</p>
<p>Changing to Is null/Is not null clears the parameter binding. Changing to Constant clears the binding and starts with empty text; choose type/value again. Other condition changes retain the parameter, so verify type compatibility.</p>
<h3>Sorting report rows</h3>
<ol><li>Select a Table in Design. Enter a row field such as <code>amount</code> in <strong>Sort by</strong>; nested paths are allowed, even for fields not displayed as columns.</li><li>Set <strong>Sort direction</strong> to <code>asc</code> (ascending, default) or <code>desc</code> (descending), then Generate preview.</li><li>Clear Sort by to remove the primary key; Clear sorting removes every key. Undo/Redo and saved projects preserve these settings.</li></ol>
<p>Filtering happens first, then sorting, then grouping. Groups follow first occurrence in sorted rows; rows retain that order inside each group. Equal sort keys keep original order in either direction. Set Sort by and Group by to the same field to order groups by key. Only this table changes; source JSON is untouched. Data → Table sorting still affects inspection only.</p>
<p>In the grouped-orders sample, amount asc gives East/South/North and Clip, Cable, Lamp, Desk, Chair, Monitor; desc gives North/South/East and Monitor, Chair, Desk, Lamp, Cable, Clip. Grand total stays 310.30. Clearing Sort by restores the original group order.</p>
<p>Non-null keys must all be decimal numbers, strings or booleans of the same type. Numbers sort numerically, strings use case-sensitive ordinal order (A, Z, a) independent of locale, and false precedes true ascending. Null sorts first ascending and last descending. Mixed types, missing fields, arrays/objects and numbers outside decimal range fail. Dates sort as text: use consistent ISO strings for chronological ordering. Up to five keys are supported; use beforeRender for computed keys or advanced transformations. Sorting by aggregate results is not supported.</p>
<h3>Multiple sort priorities</h3>
<p><strong>Add sort field</strong> adds a <strong>Then by</strong> block with Sort field and Direction. Sort by is the primary key; additional fields are applied top to bottom to refine ties. <strong>Earlier / Later</strong> reorder additional keys; the primary key stays first. Up to five keys total are supported. The added field defaults to the first unused detected field: check it before generating.</p>
<p>Types are checked separately per key, so a text customer key can precede a numeric amount key. Each key follows the same null/ordinal/decimal rules. Complete ties preserve source order in either direction. Even a low-priority key must exist and have a consistent type across all filtered rows. Fields may be nested or absent from displayed columns.</p>
<p>Try samples/multi-sort.nrtemplate with grouped-orders.data.json: customer asc then amount asc gives East Clip/Cable, North Chair/Monitor, South Lamp/Desk. Amount desc gives Cable/Clip, Monitor/Chair, Desk/Lamp. Add item desc and move it Earlier: Monitor precedes Chair within North. Total remains 310.30. Check Undo/Redo, PDF and project save/reopen.</p>
<p><strong>Remove sort</strong> or clearing Sort field removes that additional key. <strong>Clear sorting</strong> removes all keys in one Undo step. Clearing only the primary Sort by leaves the additional keys active. With no keys, source order is used before grouping. Input JSON is unchanged; sorting by aggregate results is not supported.</p>
<h3>Grouping and totals</h3>
<ol><li>Select a Table. Set <strong>Group by</strong> to a row field such as <code>customer</code>; leave blank to remove the primary level; Clear grouping removes all levels.</li><li>Choose <strong>Aggregate → Sum, Average, Min, Max or Count</strong> on columns; None disables the aggregate. Toggle <strong>Group subtotals</strong> and <strong>Grand total</strong> independently; both default on.</li><li>Generate preview. Groups follow first occurrence, with source order (or the optional sorted order) inside each group, including non-adjacent matching rows.</li></ol>
<p>Totals have a full-width Subtotal/Grand total caption followed by aligned values using each column's number format. Other cells stay blank. Without aggregates there are no totals; without grouping only the grand total appears. An empty array gives zero for Sum/Count and blank for Average/Min/Max. Save project preserves these settings; Undo/Redo applies to edits.</p>
<p>Group keys may be strings (case-sensitive), decimal numbers, booleans or null, shown as (null). Number 1 and 1.0 match; string "1" is separate. Missing keys, objects and arrays fail. Every Sum/Average/Min/Max value must be a JSON decimal number: missing values, null, numeric strings and overflow fail. Values are summed before formatting.</p>
<h3>Cross-tab tables</h3>
<p>A cross-tab turns records into a matrix, for example regions by quarter with sales at each intersection.</p>
<ol><li>Try <code>samples/cross-tab.nrtemplate</code> with <code>samples/cross-tab.data.json</code>, or prepare items with region, quarter and amount.</li><li>Choose <strong>Insert → Cross-tab</strong>. Set <strong>Data source</strong> to items, <strong>Row field</strong> to region, <strong>Column field</strong> to quarter and <strong>Value field</strong> to amount. Source paths are root-relative; field paths are record-relative. Dotted paths are supported.</li><li>Select <strong>Aggregate</strong>: sum, average, min, max or count. Count counts records without reading Value field; the others require decimal JSON numbers in every record.</li><li>Set <strong>Number format</strong> (F0–F6/N0–N6; empty preserves precision) and <strong>Font size</strong>. Toggle <strong>Row totals</strong> for the right Total column and <strong>Column totals</strong> for the bottom Grand total row.</li><li>Generate preview and export PDF. The sample shows North/Q1 30.30, North/Q2 9.70, South/Q1 −5.00, South/Q2 0.00 and grand total 35.00. With Average the grand total is 8.75. Totals aggregate original records, never averages of cells. Undo/Redo, duplication/reordering and saved projects preserve settings.</li></ol>
<p>Categories must be nonempty strings of at most 200 characters. Case and spaces are preserved and compared exactly; numbers, null, arrays, objects and missing categories fail. Convert categories to strings before rendering. Both axes use first-seen order. Missing intersections show 0 for Sum/Count and blank for Average/Min/Max. Empty arrays keep headings and enabled totals.</p>
<p>Up to three levels per axis and three measures; up to 100,000 records, 1,000 row categories and 20 column categories. Flow only, with headers repeated on subsequent pages. Columns do not split horizontally: each numeric column needs at least 40pt and row labels take double width. Reduce categories or widen the page on a width error. Long text wraps. The final total row uses ordinary matrix-row styling. Prepare filters, sorting and transformations in data/beforeRender; other tables' settings do not affect this block. No Fixed or visual filters yet.</p>
<h4>Nested axes</h4>
<ol><li>Open <code>samples/cross-tab-hierarchy.nrtemplate</code> with <code>samples/cross-tab-hierarchy.data.json</code>.</li><li>Set <strong>Row field</strong> to region. Click <strong>Add row level</strong> and set <strong>Row level 2</strong> to city. Set <strong>Column field</strong> to year, then <strong>Add column level</strong> and <strong>Column level 2</strong> to quarter.</li><li>Add up to three distinct field paths per axis, outermost first. All category values must be nonempty strings. Edit the fields to change level order. <strong>Remove row level / Remove column level</strong> removes the last level; removing level 2 restores the single-field editor. Undo/Redo preserves changes.</li><li>Generate preview: North/Central and North/Harbor stay together before South/Central. Columns are 2025/Q1, 2025/Q2, 2026/Q1. Equal child names under different parents remain independent. North/Central has Sales 60.00 and Average 30.00; grand totals are Sales 110.00 and Average 27.50.</li><li>Save the project or export PDF. All levels and measures are retained; every page repeats full column headings.</li></ol>
<p>Paths print on separate lines with repeated parent labels, with repeated row labels and no collapse controls; column headings can be merged. Optional group subtotals are described below. Siblings follow first-seen order within each parent. Limits of 1,000 rows and 20 column categories count leaf paths; width and measure limits still apply. Totals aggregate original records. In JSON, nonempty rowFields/columnFields replace rowField/columnField; empty lists restore legacy fields.</p>
<h4>Group subtotals</h4>
<ol><li>Open <code>samples/cross-tab-subtotals.nrtemplate</code> with <code>samples/cross-tab-hierarchy.data.json</code>, or select a Cross-tab with nested axes.</li><li>Enable <strong>Row group subtotals</strong> for a Subtotal row after each parent's children. Enable <strong>Column group subtotals</strong> for a Subtotal column group, with every measure, after each parent's columns.</li><li>For this dense sample, set <strong>Font size</strong> to 8 and generate preview: North Subtotal has Sales 90.00 and Average 30.00; grand totals remain 110.00 and 27.50. Subtotals use original records, never averages of displayed values or sums that include other subtotal cells.</li><li>Toggle the switches independently. You can hide <strong>Row totals</strong> and <strong>Column totals</strong> while keeping group subtotals. Undo/Redo, saved projects and PDF retain these settings. Both subtotal switches default off.</li></ol>
<p>Three-level axes subtotal the inner group first, then the outer group, including parents with one child. Single-level axes and empty data add none. Labels show the parent path followed by Subtotal. Rows use ordinary matrix styling and may continue on another page; subtotal column headings repeat. Per-level subtotal selection is not supported.</p>
<p>Subtotal columns count toward the 50 rendered-column limit and require at least 40pt per measure. On a width error, disable Column group subtotals, reduce categories/measures or widen the page. The 1,000-row and 20-column category limits count leaf paths; subtotal rows are additional (up to 2,000 for three levels). In JSON use showRowSubtotals and showColumnSubtotals.</p>
<h4>Merged column headers</h4>
<ol><li>Open <code>samples/cross-tab-merged-headers.nrtemplate</code> with <code>samples/cross-tab-hierarchy.data.json</code>, or select a Cross-tab with nested column categories or multiple measures.</li><li>Enable <strong>Merge column headers</strong> and generate preview. The sample shows 2025 once above its Q1, Q2 and Subtotal columns, and 2026 above its own Q1 and Subtotal. Sales/Average form a separate bottom header band.</li><li>Group subtotal and grand-total switches still work independently. Values stay unchanged: North 90.00/30.00, grand totals 110.00/27.50.</li><li>Save the project or export PDF. Every page repeats the complete header. Undo/Redo preserves the switch; it defaults off.</li></ol>
<p>Only column headings are merged, using the full parent path. Row labels repeat full paths unless Merge row labels is enabled separately. Total spans the category bands, while Subtotal spans the remaining bands below its parent. Explicit measure titles appear below. Long text wraps within its combined cell width. The header can become taller and change page counts; if it cannot fit with one data line, increase page height, reduce font size or disable Merge column headers. Width and column-count limits remain unchanged. In JSON set mergeColumnHeaders to true.</p>
<h4>Merged row labels</h4>
<ol><li>Open <code>samples/cross-tab-merged-rows.nrtemplate</code> with <code>samples/cross-tab-hierarchy.data.json</code>, or select a Cross-tab with nested row categories.</li><li>The sample uses A3 landscape: <strong>Page properties → Width (pt)</strong> 1190.55, <strong>Height (pt)</strong> 841.89. Enable <strong>Merge row labels</strong> and generate preview. Each row level has its own column. North appears once beside Central, Harbor and its subtotal; South/Central remains a separate group.</li><li><strong>Merge column headers</strong> works independently. Subtotal spans the remaining label columns; Grand total spans all of them. Sample totals stay 110.00/27.50.</li><li>Save the project or export PDF. Parent labels repeat beside continued groups on each new page. Undo/Redo preserves the switch, which defaults off.</li></ol>
<p>Labels use white cells with borders and left/top alignment; numeric stripes remain. Each level needs its own label column at double relative width, included in the 50-column limit. Widen the page, reduce measures/categories or disable Merge row labels if the matrix is too wide.</p>
<p>With row merging enabled, each matrix row must fit below the repeated header. Overly tall labels cause an error: increase page height, reduce font size or disable Merge row labels to restore ordinary row splitting. Text and records are never silently truncated. In JSON use mergeRowLabels.</p>
<h4>Multiple cross-tab measures</h4>
<ol><li>Click <strong>Add measure</strong> in Cross-tab properties. The current measure becomes Measure 1 (Title Value); Measure 2 starts with Count and F0.</li><li>Set each measure's unique <strong>Title</strong>, <strong>Value field</strong>, <strong>Aggregate</strong> and <strong>Number format</strong>. For example Sales/amount/sum/F2, Orders/amount/count/F0 and Average/amount/average/F2. Count does not read Value field.</li><li>Add up to three measures. <strong>Move measure up/down</strong> changes their order in every category and total. <strong>Remove measure</strong> removes the selected measure; the final one cannot be removed. With one remaining, <strong>Use single measure</strong> preserves its field, aggregate and format and removes its separate title.</li><li>Choose Page → A4 landscape and generate preview. Each column category is followed by its measure titles; the right Total group uses the same order. Grand total aggregates original records independently for each measure.</li><li>Try <code>samples/cross-tab-measures.nrtemplate</code> with <code>samples/cross-tab.data.json</code>: Sales total 35.00, Orders 4, Average 8.75; Q1 average 8.43. Save the project or export PDF. Adding, editing, removing and reordering support Undo/Redo.</li></ol>
<p>Titles must be distinct nonempty strings up to 100 characters (case-sensitive). Each category uses one column per measure. At most 50 rendered columns including row labels and totals; the page-width limit may be reached sooner. Reduce categories/measures, disable Row totals or widen the page. Empty intersections are zero for Sum/Count, blank otherwise. Existing single-measure templates remain compatible. <p>One parent-to-child level, Flow only. No Fixed master tables, arbitrary nested blocks, joins, cross-parent totals or master references in column expressions/ordinary Text. Prepare such shared data in beforeRender. Parents must be objects and every child source an array: use [] rather than null. Missing child arrays/header fields fail generation. Maximum 10,000 parents, 100,000 combined child rows before filtering and 10,000 header characters. A heading that leaves no room for table content fails generation; shorten it or reduce the font.</p>
<h3>Calculated columns</h3>
<ol><li>Select Table → Properties, add or select a column and enter its Title.</li><li>Set <strong>Expression</strong> to <code>round(row.quantity * row.price * (1 - parameters.discount), 2)</code>. Declare discount as a Number parameter with default 0.1. Row fields must contain JSON numbers.</li><li>Choose Number format F2, Alignment right and Aggregate Sum. Generate preview, then export PDF.</li><li>Use Run parameters to change discount and generate again. Expressions support Undo/Redo and saved templates/projects.</li></ol>
<p>Expression overrides Field. Clear Expression to use Field again; set a valid field if it is empty. Formulas leave source JSON unchanged. Filters, sorting and grouping still use source fields. Expressions cannot refer to another calculated column; prepare shared values in beforeRender when needed.</p>
<table><thead><tr><th>Syntax</th><th>Meaning</th></tr></thead><tbody>
<tr><td><code>row.quantity</code>, <code>row.product.price</code></td><td>Numeric field of the current row</td></tr>
<tr><td><code>parameters.discount</code></td><td>Declared Number parameter, current/default value</td></tr>
<tr><td><code>+ - * / %</code>, parentheses, unary signs</td><td>Decimal arithmetic; multiplication/division/remainder precede addition/subtraction</td></tr>
<tr><td><code>abs(x)</code>, <code>min(a,b)</code>, <code>max(a,b)</code></td><td>Absolute value, minimum, maximum</td></tr>
<tr><td><code>round(x,digits)</code></td><td>0–6 decimal places; midpoint away from zero (1.005 → 1.01 at 2 places)</td></tr>
</tbody></table>
<p>Names are case-sensitive. Row path parts start with an ASCII letter or underscore, followed by letters/digits/underscores. Use decimal literals with a dot; exponent notation such as 1e3 is not supported. Maximum 512 characters, 128 nodes and 32 nesting levels. Comparisons, numeric logic, if/coalesce/isNull and null are supported (see below). No strings, dates, JSON booleans, arrays, aggregate references or JavaScript. Numeric expressions do not require TypeScript or scripting to be enabled.</p>
<p>Missing/non-numeric values, unhandled null, division by zero and overflow fail generation. Syntax is validated even for an empty source; value errors are checked on rows surviving the table filter. Sum/Average/Min/Max use calculated values, Count counts rows. Formatting happens after calculation; use round inside the expression to round each row before summing. Pagination never multiplies totals.</p>
<p>Try <code>samples/calculated-columns.nrtemplate</code> with <code>samples/calculated-columns.data.json</code>: discount 0.1 gives Monitor 225.90, Cable 27.27, North 253.17, Desk/South 72.00 and grand total 325.17. Discount 0.2 gives 289.04. Check Preview and PDF.</p>
<h3>Calculations and conditional cell styling</h3>
<ol><li>Open samples/conditional-table.nrtemplate with samples/conditional-table.data.json. The report calculates volume discounts, handles null cost as zero, guards division by zero and colors the relevant data cells. Defaults: threshold 2, discount 0.1; net total 333.17, margin 38.17.</li><li>Select a table column in Design. Expression accepts comparisons == != &gt; &gt;= &lt; &lt;=, numeric logic &amp;&amp; || !, if(test,yes,no), coalesce(value,fallback), isNull(value) and null. A test uses 0 for false and any nonzero number for true; comparisons/logic return 0 or 1. JSON booleans and strings are not converted.</li><li>Example: <code>if(row.quantity == 0, 0, row.amount / row.quantity)</code>. Only the chosen branch executes. AND/OR short-circuit; coalesce evaluates its fallback only for null. Missing fields and invalid types still fail when accessed; coalesce is not an error handler. All branches are syntax-checked even on empty data.</li><li>Click <strong>Add style rule</strong> on a column. Set <strong>When</strong> with the same language, for example row.margin &lt; 0. Choose text color/background overrides; keep at least one enabled. Default When = 1 matches every row. Rules can refer to source numeric fields/number parameters, not another calculated column.</li><li>The first matching rule wins as a whole; later rules do not add colors. <strong>Move rule up</strong> changes priority; <strong>Remove rule</strong> deletes it. Unspecified colors retain the table text/stripe settings. Only data cells change: headings/subtotals/grand totals keep their styles. <p>Precedence, highest first: unary + - !, * / %, + -, one comparison, &amp;&amp;, ||. Parenthesize combined comparisons; chained a &lt; b &lt; c is invalid. Equality permits null (null == null is 1); ordering/arithmetic and logical tests require numbers. Formula results and When must be non-null numbers. Limits: 512 characters, 128 nodes, 32 levels per expression; 10 rules per column, 100 per table. Rule colors do not change font size, wrapping or calculations. Flow, Fixed and master-detail tables are supported. Rules do not apply to cross-tabs or charts.</p>
<h3>Nested groups</h3>

Duplicate fields, missing keys and non-scalar keys fail generation. <strong>Remove group</strong> or clearing Group field removes that level. <strong>Clear grouping</strong> removes all levels while retaining aggregate settings. <p>Average computes the decimal sum divided by the original row count, including for the grand total; it does not average group averages. Intermediate sum overflow is an error. <h3>Flow versus fixed</h3><p>Flow blocks follow each other and paginate; use flow for variable-length lists. Fixed gives X/Y/Width/Height relative to the current page's content area. Fixed blocks do not advance the flow and can overlap other blocks. A fixed text/table must fit its height or generation fails. Drag/resize uses a 2 pt grid; arrow movement is 1 pt or 10 pt with Shift. Layout alignment uses the content area inside page margins. <h3>Images and breaks</h3><p>Insert Image and use Upload image in Properties for PNG/JPEG up to 4 MB. Resources are embedded, keep their proportions, and travel with the template. <section id="dialogs"><h2>8. Design a parameter dialog</h2>

<section id="code"><h2>11. Code and report events</h2>
<p>Code is optional. Open <strong>Design → Page → Code</strong> or <strong>Dialogs → Code</strong>. Insert event creates a typed starter. Check code validates TypeScript on the server; Apply code saves the draft in the template; Cancel discards edits. Apply can save invalid code, so always Check code and then exercise actual input. <p>Scripts are disabled by default. For trusted reports, close and relaunch the installed application with <code>NEXTGEN_DESKTOP_SCRIPTS=1</code>, using the platform command in the <a href="desktop.md#trusted-report-scripts">Desktop guide</a>. The installed app includes its compiler runtime.</p>
<table><thead><tr><th>Event</th><th>When / result</th></tr></thead><tbody>
<tr><td>validateParameters(ctx: ReportContext)</td><td>After type/default checks; return ValidationError[].</td></tr>
<tr><td>beforeRender(ctx: ReportContext)</td><td>After validation; return a new JsonObject used for layout.</td></tr>
<tr><td>afterRender(ctx: AfterRenderContext)</td><td>After layout; return void or throw to reject the result.</td></tr>
</tbody></table>
<p>Example: first define required numeric <code>minimumQuantity</code> with default 3 and the items data from the exercise. Add Text <code>Selected items: {{data.selectedCount}}</code>. Then use:</p>
<pre>export function validateParameters(ctx: ReportContext): ValidationError[] {
  return ctx.parameters.minimumQuantity &lt; 0
    ? [{parameter: "minimumQuantity", message: "Enter zero or greater."}] : [];
}
export function beforeRender(ctx: ReportContext): JsonObject {
  const items = ctx.data.items.filter(item =&gt; item.quantity &gt;= ctx.parameters.minimumQuantity);
  return {...ctx.data, items, selectedCount: items.length};
}
export function afterRender(ctx: AfterRenderContext): void {
  if (ctx.result.pageCount &gt; 10) throw new Error("Narrow the selection.");
}</pre>

<p>Handlers are named synchronous exports; helper functions must not be exported. Context is read-only; return patches/new data. No imports, async, DOM, Node, filesystem, network or CLR APIs are exposed to scripts. Use deterministic data transformations. Interpreter limits are not a sandbox for untrusted public workloads.</p></section>

<section id="events"><h2>12. Dialog events and dependent choices</h2>
<p>Properties → Events opens the relevant handler for the selected object. Existing handlers are shared across the report and are selected without being rewritten. Add a branch for the selected ID/name; do not create a second same-name function.</p>
<table><thead><tr><th>Object / event</th><th>Context / return</th></tr></thead><tbody>
<tr><td>Form → Load / dialogLoad</td><td>DialogContext → DialogUpdate; open/Reset.</td></tr>
<tr><td>Field → Changed / parameterChanged</td><td>ParameterChangedContext → DialogUpdate; ctx.parameter names the parameter.</td></tr>
<tr><td>Custom button → Click / dialogButtonClick</td><td>DialogButtonContext → DialogUpdate; ctx.componentId names the button.</td></tr>
<tr><td>TabPage → Page changing / dialogPageChanging</td><td>DialogPageChangingContext → DialogNavigationResult; previousComponentId is the source, componentId the destination.</td></tr>
<tr><td>TabPage → Page changed / dialogPageChanged</td><td>DialogPageContext → DialogUpdate; componentId names the newly selected page.</td></tr>
</tbody></table>
<p>DialogUpdate supports <code>parameters</code> (new values), <code>options</code> (choices keyed by parameter), <code>components</code> (visible/enabled keyed by component ID), and <code>message</code>. Missing properties preserve state. Invalid responses are rejected atomically. Each event gets a fresh execution environment. Changed uses the browser change event, not every keystroke; programmatic patches do not recursively trigger it.</p>
<h3>Dependent choices example</h3><p>Define string ComboBox parameters country with options Ukraine/Poland and default Ukraine, and city with options Kyiv/Lviv and default Kyiv. Place both on the form. Insert:</p>
<pre>function cityChoices(country: string): string[] {
  return country === "Poland" ? ["Warsaw", "Krakow"] : ["Kyiv", "Lviv"];
}
export function dialogLoad(ctx: DialogContext): DialogUpdate {
  return {options: {city: cityChoices(ctx.parameters.country)}};
}
export function parameterChanged(ctx: ParameterChangedContext): DialogUpdate {
  if (ctx.parameter !== "country") return {};
  const choices = cityChoices(ctx.parameters.country);
  return {options: {city: choices}, parameters: {city: choices[0]}};
}</pre>
<p>Check/Apply, Run with parameters, choose Poland: city becomes Warsaw. Cancel discards the draft; successful Generate retains effective choices for preview/PDF and saved projects. Save template keeps the design's original choices. Without an explicit selected value, valid old choices survive and removed choices clear. Empty options do not waive Required. Changing report data/template invalidates committed dynamic choices.</p>
<h3>Buttons and state</h3><p>Custom Click updates the draft without submitting. Test ctx.componentId to distinguish buttons. Return <code>{components: {detailsPanel: {visible: false}}}</code> only if that unique component exists. State propagates through containers; individual TabPage state patches are not supported. Hidden/disabled values remain subject to final report validation.</p>
<h3>Cancel a transition</h3><p>Define string parameter approval, and use destination page ID confirmation:</p>
<pre>export function dialogPageChanging(ctx: DialogPageChangingContext): DialogNavigationResult {
  if (ctx.componentId === "confirmation" &amp;&amp; ctx.parameters.approval !== "yes")
    return {cancel: true, message: "Approval is required."};
  return {};
}</pre>
<p>Order: Next browser validation → Page changing → transition → Page changed. A veto preserves the page and values. Navigation results accept only cancel/message, not updates; use Page changed for updates after arrival. Initial selection, validation-error reveals and Preview form skip page events. An event exception blocks Generate until a successful event or reopen; an ordinary veto is not an exception. Closing a pending form prevents a late transition. Generate always performs final validation independently.</p></section>

<section id="limits"><h2>15. Limits and terminology</h2>
<p>Practical limits: 8 MB project/JSON uploads, 4 MB image upload, 100 dialog components, 12 parameters for automatic Create form, 50 table columns. Large datasets/layouts have additional engine limits. Latin and Cyrillic use embedded DejaVu Sans; full RTL/CJK/emoji shaping and font fallback are not implemented.</p>
<p>No MRT import, SSO/per-report ACLs, debugger or printed-block/page events. CSV/XLSX import, HTTP/SQL/JSON/object sources and Word/Excel export are available as described below. TabPage events concern input forms, not printed pages. All/Any filtering and sorting by up to five fields are available in Table Properties; advanced sorting/filtering is available through beforeRender. A .NET HTTP client and Blazor Interactive Server viewer are available. A Flutter/Dart SDK is also available. <section id="http-connections"><h2>HTTP sources and snapshot refresh</h2>

<section id="server"><h2>Server roles and schedules</h2>
<p>Without <code>NEXTGEN_SERVER_USERS</code>, Studio is a loopback-only local administrator workbench. A configured private users file enables sign-in: Viewer reads shared reports/results; Author edits, refreshes and saves reports; Admin also manages schedules. Remote access requires configured accounts and HTTPS at Kestrel.</p>
<p>The installed desktop application uses a private local session. For integration, follow the <a href="developer-guide.md#start-the-installed-engine-for-integration">installed engine instructions</a>. A shared remote server needs administrator-managed accounts and HTTPS; desktop session tokens must not be shared with clients.</p>
<ol><li>Save and verify a report in Library. Open <strong>Schedules</strong> in the footer. Admin selects a report and fixed version, PDF/HTML/XLSX/DOCX, Fixed interval or Calendar (cron), and a start date/time. Calendar mode adds a five-field cron expression and host time zone. <p>Cron fields: minute, hour, day-of-month, month, day-of-week. Use numbers, abbreviated month/day names, *, ranges, lists and steps; no seconds/year fields or special modifiers. Restricted day-of-month and day-of-week combine with AND. A fixed time in a spring DST gap moves to the first valid time; an autumn fixed time runs once, while interval-style expressions retain both repeated-hour offsets. <p>Intervals use elapsed minutes (1–525600); their next run remains claim time + interval, including Run now. Calendar rules such as <code>0 9 * * MON-FRI</code> follow the selected time zone. Start at or after is entered in your browser’s local time; the stored next run is the first matching UTC instant. Run now preserves a future calendar occurrence. Saved IANA or Windows time-zone identifiers are accepted when this host can resolve them, even if its time-zone menu uses a different naming system. Verify Preview next 5 runs after moving schedules between hosts. Invalid expressions/zones cannot overwrite saved rules. Missed periods coalesce to one execution. Viewer PDF generation uses no scripts; scripted reports should use scheduled output. Trusted Authors/Admins can use enabled host scripting.</p>
<p>Limits: 100 schedules, 32 MB/file, 200 recent runs globally and 256 MB artifact payloads. Oldest completed runs/files are removed first. Generation errors publish no artifact; folder-delivery failures retain the generated download. No email/webhook delivery, parameter overrides, delete control or multi-host worker cluster. Pause unwanted schedules. The journal is operational history, not an immutable audit log.</p>

See <a href="server-operations.md#deliver-to-a-local-folder">configuration and API examples</a>.</p>
<ol><li>As Admin, choose a named destination under <strong>Delivery</strong>, save a paused schedule, then Run now.</li><li>Refresh list: expect generation succeeded and delivery delivered. Check <code>report-&lt;run-id&gt;.pdf</code> (or html/xlsx/docx) in the server folder; Download contains identical bytes.</li><li>Enable repeating runs when ready. Choose <strong>Download only</strong> to stop copying. Active jobs keep their claimed destination. If a destination was removed, choose an available one or Download only before saving.</li></ol>
<p>Existing files are never overwritten. A delivery failure leaves the generated file downloadable; fix permissions/configuration/space and run again manually. Generation failure shows not_attempted. An interrupted run shows unknown delivery: check its run-ID filename before rerunning because a complete folder copy may already exist. No automatic retry or exactly-once crash guarantee. A crash may leave temporary files; remove them only with the scheduler stopped. Folder copies have host-managed retention and are not pruned with the run journal. Local Linux folders verified; network mounts, macOS and Windows unverified.</p>
<p>Storage: dedicated <code>App_Data/schedules.db</code>, override <code>NEXTGEN_SCHEDULES_FILE</code>. An adjacent lock prevents a second scheduler process on the same file. Cookie keys are in App_Data/keys. Stop Studio before backing up/restoring library, schedules and keys together. Protect accounts/keys/data with host permissions; they are not encrypted at rest. Forwarded-header/proxy TLS setup is not included. API clients use session cookies plus X-CSRF-TOKEN; report-tool supports --user and --password-env. Full setup: <code>docs/server-operations.md</code>. Linux iMac verified; remote HTTPS hosting, macOS and Windows remain unverified.</p></section>

<section id="composition"><h2>Page sections and imported subreports</h2>
<p>Combine portrait and landscape pages, or reuse a template from another file, in one portable report.</p>
<ol><li>In Design, choose <strong>Insert → Page section</strong>. Set Section width, height, margin, header and footer in Properties. The default is landscape A4.</li><li>Choose <strong>Edit section</strong> to add or edit its blocks. Page properties now affect that section. Use <strong>Report</strong> in the breadcrumb to return. The parent page keeps its settings. Undo/Redo includes these edits.</li><li>Choose <strong>Insert → Subreport</strong>, then <strong>Import template</strong> and select a <code>.nrtemplate</code> file. A named snapshot is saved inside the report. Choose an existing Imported template to reuse it. Set Data object path to an object such as <code>order</code>; leave blank for the current object.</li><li>Generate and inspect each Preview page. A section or subreport begins and ends at a page boundary; following content resumes the enclosing format. Footer page numbers count the complete output. Export PDF, HTML, images or Office as usual.</li><li>Save project to preserve the templates, data and parameters together. Open project works without the original child file. To update a child, import its edited file again; only the selected block switches to the new copy. Other references remain unchanged.</li></ol>
<p>Imported templates inherit same-named parameters and use their own defaults for the rest. Their data/root is the selected object, and their own images and data preparation are retained. Scripts, dialogs and connections are rejected in children; put them in the parent. A failed import leaves the draft intact. Subreports are separate pages, not inline table cells. There is no automatic file watching or runtime URL/file access.</p>
<p>Up to three combined section/subreport/drill-down levels and 20 imported templates per template. Page sections cannot be inside repeats; put a repeat inside a page section. Imports can be repeated per record. Empty sections are invalid. Existing Office editable-text and custom Excel paper-size limits still apply.</p>
<p>Example: <a href="http://127.0.0.1:5274/samples/composed-report.nrtemplate">composed template</a>, <a href="http://127.0.0.1:5274/samples/composed-report.data.json">sample data</a>, <a href="http://127.0.0.1:5274/samples/order-subreport.nrtemplate">standalone child</a>. Expected output: four pages, with a landscape overview and a portrait order totaling 155.50. See <a href="template-format.md#page-sections-and-imported-subreports">format details</a>.</p></section>
<section id="desktop"><h2>28. Desktop Studio</h2>
<p>Open <strong>Nextgen Reports Desktop</strong> from the desktop, or use the demo launcher's <strong>Open desktop Studio</strong> action. The separate window starts its own local engine and sample report; it does not use the browser demo's Library.</p>
<ol><li>Choose <strong>File → Open project…</strong> to open a portable project. Generate preview after editing.</li><li>Choose <strong>File → Save project as…</strong> for a native save dialog. Export PDF/Office/images/HTML through the existing controls.</li><li>Save a Library version to retain it between launches. Desktop also saves a recovery draft every three seconds while idle. On restart, choose Restore draft, Discard draft or Quit. Restoring does not generate a preview; fix unfinished JSON and choose Generate preview.</li><li>Use <strong>Help → Developer guide &amp; code examples</strong> for local English code examples.</li><li>Use File → Save recovery draft now or Delete recovery draft… to manage the local draft. Normal closing captures final edits; a failed capture asks whether to keep working. Closing stops the owned engine. Other browser demo processes remain available.</li></ol>
<p>Recovery keeps raw template/data text and applied parameter controls, up to 16 MB. Open dialogs and active generation/export pause capture; modal edits, undo history and preview pages are not saved. The draft follows the current workspace and contains local report data. Save files or Library versions before switching projects. Damaged recovery files are preserved with automatic saving paused.</p>

Use Help → Check for updates to download and confirm a restart; the app saves a recovery draft first. Unsigned macOS builds cannot auto-install updates. Linux GUI is checked locally; Windows/macOS GUI and signed distribution remain unverified. See the desktop guide for platform installation steps and limitations.</p></section>
