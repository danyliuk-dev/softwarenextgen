Behavior and practical rules

Categories define the shared domain; every series must have the same number of nullable numeric values. Null breaks a line instead of becoming zero. Point selection returns NgChartSelection with zero-based series/point indices, their names, the number and a ready-to-use label. The application chooses what to do with a point. Keep units explicit. See analytics and scheduling for mode-specific constraints; advanced axes, export, remote aggregation and broad chart-type parity are not implemented. HiddenSeries/hiddenSeries is optional: null keeps internal legend state, a set enables controlled visibility. HiddenSeriesChanged/onHiddenSeriesChanged proposes a fresh set; the parent must accept it. A controlled set without a callback is noninteractive. Unknown indices are ignored by drawing and retained in controlled proposals; the parent owns pruning and reordering. Series identity is its zero-based index. Keep the same ownership mode for the lifetime of a chart; returning to internal mode resumes its prior internal state. LegendReadOnly/legendReadOnly freezes user legend changes, while SelectionReadOnly/selectionReadOnly blocks point actions without hiding their data or tooltips. Programmatic visibility updates still work. PointLabel/pointLabel returns plain text for tooltips, point actions, accessible names and selected-point status; it does not change numeric values or axes. EmptyText/emptyText customizes the empty chart message. Selection survives equivalent data replacement, but clears when the selected point is hidden, removed, renamed or changes value, or when data becomes invalid. Invalid data recovery does not restore stale selection. Captured point callbacks are rejected if they no longer match a visible current point. This is chart-owned selection, not a controlled selection API.

Integration and troubleshooting

If the UI does not update, confirm that the parent stores callback values and passes them back. Blazor event handlers need interactive rendering; Flutter requires setState or a state manager. Submit form data only after successful validation.

Check accessible labels, empty/invalid states, disabled actions and narrow layouts. Keyboard support is not full screen-reader certification. Current visual verification targets Web in visible Chrome on Linux/iMac; native mobile platforms are a separate phase.
