Developer guide and code examples

Start with a complete working example, then choose the integration for your app. Commands use the installed product and SDK. Examples contain fictional data. Build only your own application; the supplied libraries and engine are ready to use.

Installed SDK and first connection

Install Nextgen Reports, then copy its SDK folder into your application's vendor/nextgen-sdk. The package contains prebuilt .NET NuGet libraries and a Flutter/Dart package. The desktop app can author reports immediately; development tools are needed only for building your own application.

The engine is self-contained: do not install .NET or build Studio just to run it.

Local mode is for trusted applications on your computer. Do not change the binding to a public interface. A remote integration requires a separately administered HTTPS server and per-user access controls. Mobile applications cannot reach your computer through the phone's localhost.

Use Flutter and Dart

Add the installed SDK package as in Flutter setup. For Flutter Web, serve the app from Studio's origin; Uri.base.resolve('/') uses that origin. Native Dart hosts use an explicit HTTPS server URL.

The download callback above marks the host integration point; it does not save files by itself. The runnable Web demo includes the complete Blob download flow. Objects need toJson(); dates need explicit JSON conversion. Assign new input snapshots after edits and close the client when finished. Full code covers login, refresh, cancellation, errors, export options and platform limits in the Flutter setup guide. Android/iOS devices and native desktop GUI remain unverified.

Connect SQL, JSON files and application objects

Direct JSON/C# objects require no catalog. For external refresh, the host supplies source IDs, queries, connection environment variables or callbacks; the report stores bindings and a saved data snapshot. Supported providers: PostgreSQL, SQL Server, MySQL, MariaDB and SQLite, plus JSON files and .NET object callbacks.

Save this host catalog outside the report and set NEXTGEN_DATA_SOURCES to its absolute path; set REPORTS_DATABASE in the host environment. Create the orders table/data in your own database. In Studio Connections choose sales, target items, empty array path, and bind source region to a string report parameter. Refresh, inspect and Apply snapshot before generating. No refresh occurs implicitly. See data sources for all five provider configurations, JSON file and object callback code, expected sample totals, limits and SQL Server's current live-verification limitation. Never put connection secrets in report parameters.

Export modes and expected results

Format/mode Result
PDF Paginated report with embedded fonts
HTML Standalone pages with embedded fonts/images
Excel/Word editable Displayed text in editable cells/paragraphs; graphics omitted
Excel/Word exact pages Complete pages as PNG images; text is not independently editable

Editable Office does not preserve original typed numbers/formulas or native Office charts. Exact pages supports page range and DPI. See Office export and page image export for API/CLI examples and limits.

Read and copy code examples

Code blocks use local syntax highlighting for C#, Dart, TypeScript, JSON, Razor markup and shell commands. Different colors identify keywords, strings, numbers, comments, types and properties. Select Copy code above a block to copy its original source without formatting. Highlighting works without an external CDN; JavaScript must be enabled. Razor examples highlight markup; embedded C# expressions may use the default text color.
