Nextgen Reports documentation

Installed examples: copy SDK from the application resources to a writable folder and run tool commands from that copied SDK folder. It contains tools/ and samples/. Python tools require Python 3 and connect to the installed integration engine; they do not compile the product. Adjust --base if you chose a different port. Output paths are relative to your working folder.

All guides and demo UI are in English. Examples use fictional data. Programming is optional for report authors; application developers can start with runnable code.

Learn by doing

  1. Open a sample project, change a parameter and generate Preview/PDF.
  2. Follow Build your first report in the authoring manual. Create a three-row table, heading and page numbers; save and reopen the project.
  3. Add a company parameter and test Cancel/Generate in the parameter form.
  4. Build two dialog pages with Next/Back and test required fields and sequential steps.
  5. Read the event guide and try samples/inventory.nrtemplate for validation and filtering.
  6. Follow the developer guide to connect the installed SDK and generate outputs from your own C# application.
  7. Open the Blazor or Flutter demo, change data and inspect the corresponding code guide.

Read in the browser

Studio Manual ↗ or Code → Manual opens the local English authoring guide. Its Developer guide & code examples link opens readable code, with links to local .NET, Flutter and data-source guides. The desktop launcher's documentation action opens the developer guide directly. No GitHub connection is needed. The developer hub uses three numbered cards to explain the learning path; code blocks have language labels, syntax colors and Copy code. A successful copy shows Copied. On restricted browser contexts, select and copy the text manually. Narrow screens stack the cards; long code lines scroll inside their code block.
